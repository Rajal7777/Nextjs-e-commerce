Key Flow Security Checkpoints
Step 2 & Step 5 (Generic Masking): The server returns the exact same success notification to the UI regardless of whether the email was found. This halts malicious bot attacks attempting to scrape registered user lists.
Step 3 & Step 9 (Token Disconnect): The plaintext RAW_TOKEN travels exclusively to the user's inbox. The Database only receives and stores the cryptographically secure bcrypt hash of that token. This setup ensures that even a total database compromise does not expose active password-override links.
Step 10 (Atomicity): Updating the target profile password and scrubbing the token registry are bundled into a single Prisma database transaction block. If either step stumbles, the whole operation rolls back to preserve security integrity.
